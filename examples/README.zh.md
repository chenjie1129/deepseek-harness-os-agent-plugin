## 1. App 回归流程走查

端到端跑通一个多步骤流程，并保留录屏作为证据。适合发版前的冒烟测试。

**前置条件：** 已配置 TOS Bucket、Endpoint 与 Region（录屏需要）。

**提示词：**

```
在云手机上跑一次回归，并录屏：

1. 打开 App "MyShop"。
2. 用一个新手机号注册，短信验证码填 000000。
3. 把首页第一个商品加入购物车。
4. 进入购物车并进入结算流程，但在付款前停下。

启动任务时开启录屏。轮询状态直到运行结束，然后汇报：哪一步失败了（如果有）、
最终界面显示了什么、以及录屏文件的位置。
```

**智能体会做什么：** 带 `screen_record: true` 和一个有辨识度的 `run_name` 调用 `mobile_use_start_task`，轮询 `mobile_use_get_status`，最后读取 `mobile_use_get_result`。

**变体**

- 长流程要放宽步数预算：在设置里把*最大步骤数*调到 200–300。
- 想换数据重复跑，就要求跑多次，每次用不同的 `run_name`。

## 2. 应用商店竞品扫描

提取只在移动端 App 内可见的排名或价格数据。

**提示词：**

```
在云手机上打开应用商店，搜索"习惯打卡"，汇报前 5 个结果：App 名称、开发者、
评分、以及是否显示广告或内购。用 markdown 表格返回数据。
```

**智能体会做什么：** 一次 `mobile_use_start_task`，然后轮询并汇报。不录屏，所以不需要 TOS。

**变体**

- 想追踪变化趋势，就每天定时跑同一段提示词并对比结果差异。
- 加一句 `再打开排名第一的那个 App，总结它的截图展示区。` 可以再往下钻一层。

## 3. 跨 App 数据流转

验证数据在两个 App 之间搬运后是否完好——这种流程写脚本很痛苦，但用自然语言描述很轻松。

**提示词：**

```
在云手机上：

1. 打开备忘录，新建一条标题为 "handoff-check"、正文为 "42" 的记录。
2. 复制正文内容。
3. 打开浏览器，访问 example.com，把复制的文本粘贴到搜索框，但不要提交。
4. 汇报粘贴进去的文本是否正好是 "42"。

如果任何一步无法完成，就停下来告诉我是哪一步、以及原因。
```

**智能体会做什么：** 一次运行即覆盖两个 App，App 切换由 Mobile Use 内部处理。明确写出"停下来告诉我"能让失败可诊断，而不是被静默重试掉。

**变体**

- 换成你自己的 App：分享面板、剪贴板流程、deep link 都适用。
- 加一句 `记录你遇到的任何权限弹窗的确切文案。` 可以捕捉首次运行的权限提示。

## 4. 无头脚本

`headless-run.mjs` 直接调用同样的三个 Mobile Use 操作，不依赖 Harness，也不需要模型。用它在排查智能体层问题之前，先确认密钥、Product Id 与 PodId 是否正确。

```sh
VOLC_ACCESSKEY=你的-access-key \
VOLC_SECRETKEY=你的-secret-key \
OS_AGENT_PRODUCT_ID=你的-product-id \
OS_AGENT_POD_ID=你的-pod-id \
node headless-run.mjs "打开设置并报告 Android 版本号"
```

可选环境变量：

| 变量 | 默认值 | 含义 |
|---|---|---|
| `OS_AGENT_MAX_STEPS` | `100` | 本次运行的步数预算（1–500） |
| `OS_AGENT_TIMEOUT` | `120` | 运行超时秒数（1–86,400） |
| `OS_AGENT_SYSTEM_PROMPT` | *(空)* | 传给 Mobile Use 的额外指令 |
| `OS_AGENT_POLL_INTERVAL` | `5` | 两次状态轮询之间的间隔秒数 |
| `OS_AGENT_POLL_LIMIT` | `60` | 放弃前的最大轮询次数 |

脚本会打印 `RunId`、每次轮询一行日志、以及最终结果内容。遇到 API 错误时以非零状态码退出，因此也可以当作 CI 冒烟检查使用。

## 实践建议

- **明确写出"到哪儿停"。** 告诉智能体*不要*做什么（比如"在付款前停下"）——云手机是真的会把订单付掉的。
- **给运行起名字。** 传 `run_name` 能让你之后在火山引擎控制台里更容易找到对应运行。
- **延续会话。** 当后续任务需要保留之前的上下文时，传上一次的 `thread_id`。
- **合理设置步数预算。** 默认 100 步适合短流程；长回归需要更多，而预算过小看起来就像莫名其妙地提前停止。
- **绝不要把密钥写进提示词。** 插件会从 credential store 解析密钥；system prompt 也已经告知模型不要凭空编造这些值。
